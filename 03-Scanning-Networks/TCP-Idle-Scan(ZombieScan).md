
# TCP Idle Scan (Zombie Scan)

TCP Idle Scan, also known as Zombie Scan, is an advanced TCP port scanning technique that allows an attacker to scan a target indirectly through a third-party host called a **Zombie**.

Instead of sending scanning packets directly to the target using its own IP address, the attacker uses the Zombie's IP address as the apparent source of the probes.

This technique relies on predictable IP ID (IP Identification) values generated by the Zombie host.

## Key Concepts

### 1. Zombie Host

A Zombie is an idle third-party system used by the scanner to indirectly probe a target.

An appropriate Zombie should:
- Be relatively inactive during the scan.
- Generate predictable and incremental IP ID values.
- Allow the scanner to observe changes in its IP ID sequence.

### 2. IP ID (IP Identification)

IP ID is a field in the IPv4 header used to identify and reassemble fragmented IP packets.

Some operating systems generate IP ID values sequentially, incrementing the value when sending packets.

For example:

```text
IP ID = 31337
IP ID = 31338
IP ID = 31339
IP ID = 31340
```

By monitoring changes in these values, the scanner can infer whether the Zombie has sent additional packets.

This behavior is the foundation of the Idle Scan technique.

## How TCP Idle Scan Works

Idle Scan involves three main steps.

### Step 1: Probe the Zombie

The attacker sends a probe packet to the Zombie, typically a TCP SYN/ACK packet.

Since the Zombie has no established connection corresponding to this packet, it responds with a TCP RST packet.

The attacker examines the IP ID value in the response and records it as the initial value.

Example:

```text
Initial IP ID = 31337
```

### Step 2: Send a Spoofed Packet to the Target

The attacker sends a TCP SYN packet to the target, but spoofs the source IP address so that the packet appears to come from the Zombie.

The target responds according to the state of the destination port.

#### If the Target Port Is Open

1. The target receives the SYN packet.
2. The target responds with SYN/ACK.
3. The response is sent to the Zombie because the packet's source IP was spoofed.
4. The Zombie receives an unexpected SYN/ACK packet and responds with RST.
5. Sending this additional RST packet increments the Zombie's IP ID value.

#### If the Target Port Is Closed

1. The target receives the SYN packet.
2. The target responds with RST.
3. The RST packet is sent to the Zombie.
4. The Zombie ignores the unsolicited RST packet.
5. No additional packet is generated by the Zombie, so its IP ID does not increment because of this interaction.

### Step 3: Probe the Zombie Again

The attacker sends another probe to the Zombie and examines its new IP ID value.

The attacker compares the new value with the initial value to determine whether the Zombie sent an additional packet.

## Understanding IP ID Changes

Consider the following example:

**Initial Probe:**

```text
Zombie IP ID = 31337
```

After sending the spoofed SYN packet:

### Case 1: Target Port Is Open

The Zombie receives a SYN/ACK and sends an RST packet.

This causes an additional IP ID increment.

```text
Initial IP ID = 31337
Final IP ID   = 31339

Difference = 2
```

The increase of two indicates:
- One increment from the Zombie's response to the attacker's first probe.
- One additional increment caused by its response to the target.

**Result: The target port is likely open.**

### Case 2: Target Port Is Closed

The Zombie receives an unsolicited RST packet and ignores it.

```text
Initial IP ID = 31337
Final IP ID   = 31338

Difference = 1
```

Only the Zombie's response to the attacker's second probe increments the IP ID.

**Result: The target port is closed or filtered.**

## Nmap Command

Nmap uses the `-sI` option to perform an Idle Scan.

```bash
nmap -Pn -sI <zombie-host> <target>
```

### Example

```bash
nmap -Pn -sI 10.10.10.20 10.10.10.10
```

In this example:

- `10.10.10.20`: Zombie host.
- `10.10.10.10`: Target host.
- `-sI`: Performs an Idle Scan.
- `-Pn`: Skips host discovery and treats the target as online.

To scan a specific port:

```bash
nmap -Pn -sI 10.10.10.20 -p 80 10.10.10.10
```

To scan multiple ports:

```bash
nmap -Pn -sI 10.10.10.20 -p 22,80,443 10.10.10.10
```

**Important:** Idle Scan requires a suitable Zombie host and the ability to send spoofed packets. It may be unreliable if the Zombie generates unpredictable IP ID values or receives unrelated network traffic during the scan.

## Characteristics of Idle Scan

- Uses a third-party system called a Zombie.
- Does not send the spoofed scanning probes directly from the attacker's IP address to the target.
- Relies on predictable IP ID sequences.
- Can help identify open ports indirectly.
- Can make the Zombie appear to be the source of the scan.
- Is generally slower and more complex than conventional TCP scans.
- Requires a suitable Zombie and support for IP spoofing.

## Advantages

- Hides the attacker's actual IP address from the target's scanning logs.
- Can help examine systems protected by IP-based trust relationships.
- Provides an indirect method of port discovery.

## Limitations

- Finding a suitable Zombie can be difficult.
- The Zombie must have predictable IP ID behavior.
- Background traffic can affect scan accuracy.
- IP spoofing may be blocked by network providers or security devices.
- The scan is generally slower than ordinary TCP scans.

## Summary

TCP Idle Scan is an indirect port scanning technique that uses a third-party system to probe a target.

It works by monitoring changes in the Zombie's IP ID values.

The basic interpretation is:

- **IP ID increases by 2:** The target port is likely open.
- **IP ID increases by 1:** The target port is closed or filtered.

Nmap performs this scan using the `-sI` option.
