
# Patch Management

## Overview

**Patch Management** is the process of identifying, selecting, testing, deploying, and maintaining software updates to fix known vulnerabilities and improve system security.

Patches help organizations keep their operating systems, applications, and servers secure and stable.

Without proper patch management, systems may remain vulnerable to known security weaknesses.

## 1. Patches

A **Patch** is a software update designed to fix problems or improve an existing application or operating system.

Patches may address:

- Security vulnerabilities
- Software bugs
- Stability issues
- Performance problems
- Compatibility problems

Security patches are particularly important because they help prevent attackers from exploiting known vulnerabilities.

## 2. Hotfixes

A **Hotfix** is a specific software update designed to address an urgent problem, usually a critical bug or security vulnerability.

Hotfixes are generally released outside the regular update cycle when an immediate correction is necessary.

Unlike regular updates, hotfixes are not always publicly announced.

## 3. Patch Management Process

Patch Management ensures that required patches are properly evaluated and installed on systems.

The process involves several important activities.

### 3.1 Patch Selection

Identify and select patches that are relevant to the operating systems, applications, and software running in the environment.

### 3.2 Patch Approval

Review selected patches and approve them before deployment.

Approval helps ensure that patches are appropriate for the target systems.

### 3.3 Patch Testing

Test patches in a controlled environment before installing them on production systems.

Testing helps identify potential compatibility problems or unexpected effects on system functionality.

### 3.4 Patch Deployment

Deploy approved patches to the appropriate systems.

Deployment should follow a planned process to reduce the risk of service disruption.

### 3.5 Updating Previously Applied Patches

Replace or update previously installed patches when newer versions become available.

This helps ensure that systems remain protected against known vulnerabilities.

### 3.6 Patch Inventory

Maintain a list of previously installed patches on existing software and systems.

An accurate inventory helps administrators understand the current patch status of the environment.

### 3.7 Patch Repository

Create and maintain a centralized **Patch Repository**.

A repository stores patches in one location, making it easier for administrators to select and manage them.

### 3.8 Patch Assignment and Installation

Assign appropriate patches to the relevant systems and install them.

Administrators should verify that installation is successful and that the systems continue to operate correctly.

## 4. Patch Management Tasks

The main responsibilities of patch management include:

- Selecting, approving, testing, and applying patches.
- Updating previously installed patches with current versions.
- Listing patches previously applied to existing software.
- Creating a patch repository for easier patch selection.
- Assigning and installing patches on target systems.

## 5. Patch Management Tools

The PDF introduces the following tools for patch management:

### 5.1 Symantec Client Management Suite

A systems management solution historically used to manage endpoints, software deployment, and patch-related operations.

### 5.2 SolarWinds Patch Manager

A patch management solution designed to help administrators manage and deploy updates across Windows-based environments.

### 5.3 Software Vulnerability Manager (Flexera Software)

A vulnerability and software risk management solution used to identify software weaknesses and support remediation.

### 5.4 Ivanti Patch for Endpoint Manager

A patch management solution used to manage and deploy software updates across endpoint systems.

### 5.5 Microsoft Baseline Security Analyzer (MBSA)

A Microsoft security assessment tool that historically helped identify missing security updates and common Windows configuration weaknesses.

**Note:** MBSA is a discontinued legacy tool and should not be considered a current patch management solution.

### 5.6 Altiris Client Management Suite

A legacy endpoint management solution associated with software distribution, system management, and patch-related operations.

### 5.7 GFI LanGuard

A network security and vulnerability management tool that can identify missing patches and help administrators manage updates.

### 5.8 Kaseya Security Patch Management

A patch management solution used to manage and deploy updates across managed IT systems.

### 5.9 ZENworks Patch Management

A patch management solution from the Micro Focus/OpenText ZENworks product family.

It supports the management and deployment of software patches.

### 5.10 Security Manager Plus

A vulnerability management solution designed to identify security weaknesses and support remediation activities.

### 5.11 Prism Suite

A management and security solution listed in the course material as a patch management tool.

### 5.12 MaaS360 Patch Analyzer Tool

A tool associated with IBM MaaS360 endpoint management and patch assessment.

### 5.13 Secunia CSI

**Secunia Corporate Software Inspector (CSI)** was a software vulnerability and patch management solution.

It helped organizations identify vulnerable software and manage security updates.

### 5.14 Lumension Patch and Remediation

A patch and remediation solution used to identify missing updates and address endpoint security weaknesses.

### 5.15 VMware vCenter Protect

A security and patch management product historically used to assess and manage vulnerabilities and updates in managed environments.

## Summary

- Patch Management is the process of managing software updates to fix vulnerabilities and improve system security.
- A Patch can address security vulnerabilities, software bugs, and stability problems.
- A Hotfix is an urgent update designed to correct a specific problem.
- Patch Management includes selecting, approving, testing, deploying, and maintaining patches.
- A Patch Repository provides centralized storage for managing available patches.
- Patch inventory helps administrators track previously installed updates.
- Tools such as SolarWinds Patch Manager, GFI LanGuard, Ivanti, and Secunia CSI are listed in the course material.
- Some tools in the PDF are legacy products and may no longer be supported.
- A proper patch management process reduces the risk of exploitation of known vulnerabilities.
