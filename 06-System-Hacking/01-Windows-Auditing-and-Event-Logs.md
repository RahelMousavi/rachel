
# Windows Auditing and Event Logs

## Introduction to Covering Tracks

**Covering Tracks** refers to techniques used by an attacker to hide evidence of unauthorized activities after gaining access to a system.

After compromising a target, an attacker may attempt to make their activities more difficult to detect by manipulating system records and forensic artifacts.

Common techniques include:

- Disabling system auditing.
- Deleting event logs.
- Modifying event records.
- Removing or altering system activity traces.

These techniques are associated with the post-compromise stage of an attack.

From a defensive perspective, understanding them helps security professionals detect suspicious activity and preserve forensic evidence.

## Windows Auditing

**Windows Auditing** is a security feature that records selected activities and events occurring on a Windows system.

It helps administrators monitor user activity, authentication attempts, system changes, and other security-related events.

Auditing can record events such as:

- Successful and failed logon attempts.
- Account management activities.
- Changes to security policies.
- Access to sensitive objects.
- System integrity events.
- Privilege-related activities.

Auditing policies determine which activities are recorded.

### Audit Policy Categories

Windows auditing includes several categories, such as:

- **Account Logon:** Records events related to validating account credentials.
- **Logon/Logoff:** Records user logon and logoff activity.
- **Account Management:** Records changes to user and group accounts.
- **Policy Change:** Records changes to security policies.
- **System:** Records system-level security events.
- **Object Access:** Records access to configured files, folders, and other objects.
- **Privilege Use:** Records certain uses of user privileges.

The exact events recorded depend on the configured audit policies and the Windows version.

## Auditpol

**Auditpol** is a Windows command-line utility used to view and manage audit policies.

It allows administrators to inspect auditing configuration and verify which events are configured for monitoring.

To display the current audit policy configuration:

```cmd
auditpol /get /category:*
```

This command displays the auditing settings for all available categories.

Administrators can use Auditpol to review and configure auditing policies. Changes to these settings should be authorized and documented.

### Why Is Auditpol Important?

Attackers with sufficient privileges may attempt to weaken auditing settings to reduce the amount of evidence generated by their activities.

For defenders, unexpected changes to audit policies can indicate suspicious behavior.

Monitoring should focus on:

- Unexpected disabling of audit categories.
- Changes to logon and account auditing.
- Unusual changes to security policies.
- Audit policy modifications by unexpected accounts or processes.

## Windows Event Logs

**Windows Event Logs** store records of events generated by the operating system and applications.

Administrators and security analysts use these records to investigate system behavior and identify suspicious activities.

The main Windows event log categories include:

### 1. Application Log

Contains events generated by applications and software running on the system.

These events may include application errors, warnings, and informational messages.

### 2. Security Log

Contains security-related events, including:

- Successful and failed logon attempts.
- Account management activities.
- Audit policy changes.
- Object access events, when auditing is configured.

This log is particularly important during security investigations.

### 3. System Log

Contains events generated by Windows system components, drivers, and services.

It can help identify startup problems, service failures, and system-level changes.

### 4. Setup Log

Contains events related to Windows installation and setup operations.

### 5. Forwarded Events

Contains events collected from other computers and forwarded to the local system.

This is useful in centralized monitoring environments.

## Event Log Manipulation

An attacker may attempt to interfere with event logs to hide evidence of unauthorized activities.

Two techniques commonly associated with covering tracks are:

### 1. Clearing Event Logs

Clearing an event log removes existing records from that log.

The course mentions tools such as `clearlogs.exe` and Metasploit Meterpreter as examples associated with event-log clearing.

The removal of logs can make investigations more difficult, but it may also generate additional evidence.

For example, Windows can record an event indicating that an audit log was cleared.

### 2. Modifying Event Logs

Instead of removing an entire log, an attacker may attempt to modify or manipulate individual records.

This can make it harder to reconstruct the sequence of events during an investigation.

However, Windows event logs are not the only source of evidence. Other systems may contain copies or related records.

## Detecting Event Log Tampering

Security teams should monitor event-log activity and investigate unexpected changes.

Important indicators include:

- Event logs being cleared unexpectedly.
- Auditing settings being changed without authorization.
- Gaps in expected event records.
- Unusual administrative activity.
- Security-related services being stopped or modified.

### Centralized Logging

A useful defensive measure is to forward event logs to a centralized logging platform.

If logs are stored on a separate, protected system, an attacker who compromises one endpoint may have a harder time deleting all available evidence.

Centralized logging also helps analysts correlate events across multiple systems.

## Summary

Covering Tracks refers to techniques used to hide evidence of unauthorized activities.

In Windows, attackers may attempt to interfere with auditing and event logs by disabling auditing, clearing logs, or modifying event records.

Important concepts include:

- **Windows Auditing:** Records selected security-related activities.
- **Auditpol:** A command-line utility for inspecting and managing audit policies.
- **Event Logs:** Store application, security, system, setup, and forwarded events.
- **Event Log Tampering:** Attempts to remove or manipulate records to make investigations more difficult.

Centralized logging, restricted administrative access, and monitoring audit-policy changes help detect and reduce the impact of these techniques.
